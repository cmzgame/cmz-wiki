## The law: the code is the truth

The wiki describes the game on `main` as the code has it. Where the game's docs disagree with its code, the wiki follows the code and the disagreement goes to `census/discrepancies.md`. Where the code looks wrong, the wiki still describes it as it is, and the finding goes to the game's `docs/bugs.md`. A page never chooses silently.

## A sync (every time the game's `main` moves)

Michael's rule (2026-10-14, its order ruled 2026-10-15): a feature, a fix, or a change to a number is not done until the wiki is checked and updated for it, **in the same session as its merge to the game's `main`**; the sync reads `origin/main`, so it follows the merge; a batch of merges in one session is synced once, at its end. In order:

1. **`node sync.js`**: snapshot `origin/main`: its data into `snapshot/` (committed; what the build reads) and its code, tools, and docs into `.game/` (ignored; what the census and writers read). `snapshot/version.json` records the commit. The snapshot is the game's `data/` without its art: `data/art/**`, `data/hair/**`, `data/layers/**`, and `data/site/**` (the game's site shots) are left out (some three hundred PNGs that nothing here reads) but for the item icons `items.json` names and `data/hair/index.json`, which the build and the census read.
2. **Read what changed:** `git -C ../cozy-medieval-zombies log --oneline <last commit>..origin/main` (the last commit is in the previous `snapshot/version.json` or the latest Updates entry), the merged pull requests' bodies (each names its wiki effect), and the newest entries at the top of the game's `docs/02-decisions.md`.
3. **`node census/census.js`**: the automatic inventory (`census/census.md`, `census/census.json`): counts, items, recipes, loot, props, places, settings, keys, verbs, menu labels, moodles, events, checks, and the code's named constants (`census.constants`). It also reports problems the data shows by itself.
4. **Read the game's `docs/bugs.md`** for lines moved since the last sync: to **Became issues** (the issue says what changed when it closes), to **Fixed** (a page may describe the old behaviour as current: grep the pages for it and correct it, with a Sources line naming the fixing commit), or to **Closed** (the behaviour is intended; a page may need to say so). The items fixed up to 2026-10-15 are the game's `docs/history/bugs-fixed-2026-10-15.md` (the sweep, 2026-10-16); new fixes go to the live file's Fixed as before.
5. **Update the pages** the changes touch: correct what changed, write pages for what is new (`WRITING.md`), replace `{{planned}}` notes for things now built (`Special:Planned notes` lists them), and bump a page's `<!-- sources at ... -->` to the new commit when its sources are rechecked. A rule that lives only in code (not in `data/`) reaches a page only this way, so read the log for behaviour, not just numbers. **The Sources-drift report** (`node build.js --check`, the lines after the summary) names each page whose cited lines (`path:first-last`) the game changed between the page's `sources at` commit and the snapshot's, read from the game's repository with a read-only `git diff` (`../cozy-medieval-zombies`, or `CMZ_GAME`): a drifted page is the one to recheck first; the report only reports, it fails nothing.
6. **`node build.js --check`**: it fails on a template naming something the data no longer has, a duplicate page name, a missing icon, and a number typed into prose; it reports red links, planned notes, and generated-only pages. Fix what it names.
7. **An entry on the Updates page** (`pages/front/updates.md`): one entry per sync with the date and the game commit, a bullet per game change saying what changed on the wiki (or that nothing visible did).
8. **New bugs found on the way go to the game's `docs/bugs.md`** under Open, on top of the latest `main`, after a check of Became issues, Fixed, and Closed so nothing settled comes back: what happens, where in the code (file and line at a stated commit), *needs repro* if inferred; behaviour that may be intended goes under "surprises for Michael to rule on". Never into a page as a choice.
9. **Commit and push** this repository through `gh`'s credential while the bot is flagged (`github.md`'s box). The site republishes in a minute or two (`gh run list -R cmzgame/cmz-wiki`).

## The census, and redoing it

The census is the inventory of what the game contains, done once in full (2026-10-14, at `9205ad7`) and redone by area when a large change lands. `census/census.js` is automatic (step 3). **The six fact sheets** (world, player, combat, items, building, multiplayer-ui) were read from the code by six parallel agents, each told: code and data are the truth, docs second; one section per mechanic with **Rule**, **Numbers** (each with its data path or `src/file.js:line`), **Code**, **With friends**, **Docs differ**, **Confidence**; then candidate pages and discrepancies; read only, write one file. **The records of the first census are dated**, under `census/history/9205ad7/` (the sheets in `areas/`, `findings.md`, and the docs-versus-code list as it stood, each with a banner saying so): a record is never edited. To redo an area, give an agent that brief with the area's scope and the new commit and have it write a fresh sheet under `census/history/<commit>/areas/`; a sheet's line numbers are for its commit, so confirm a line in `.game/` before citing it. **`census/discrepancies.md` is the live list**, short, of what is still a discrepancy at the snapshot's commit: when it is rechecked it is rewritten whole at the new commit, with the old one filed under `census/history/<commit>/`; nothing is amended in place with a "Resolved at" tail any more (the sweep, 2026-10-16). **A large batch of pages** is written the same way: parallel agents, one per folder of `pages/`, each given `WRITING.md`, `lib/templates.js`, its fact sheet, an exact list of page titles, a folder of its own, and `node build.js --out .tmp-<name>` to check its work without touching `site/`.

## Verification, and the game going private

Every page shows **Verify** and how long since its stamp, or an orange "Changed since verified" once its text differs from the fingerprint stamped with it; Verify opens an issue `Verify: <page title>` that only Michael's account may submit (the workflow's `VERIFIER` stamps `verified.json` and republishes). **No agent ever opens a Verify issue.** `verification.txt` after a build lists the stalest pages. Sources link to the game's repository at the commit they were read from (`GAME_REPO`, `LINK_SOURCES` in `build.js`); when the game goes private, set `LINK_SOURCES = false` and this repository goes private with it (Michael, 2026-10-14).

## The tools

- `sync.js` the snapshot; `census/census.js` the inventory; `build.js` the build (`--check`, `--out <dir>`; `--out .tmp-<name>` checks a batch without touching `site/`); `serve.js` a local preview at http://localhost:8020 (the game's `.claude/launch.json` names it `wiki`).
- `lib/markdown.js` the renderer (written here; no dependencies anywhere), `lib/data.js` the data and `lookup` for `{{n}}`, `lib/templates.js` every template, `lib/mapimage.js` the valley's map drawn from the map file at the screen's angle (PNG by zlib). `assets/` the style and the search.

## Gotchas learned the hard way

- **The `gh` token on Michael's machine cannot change repository settings or dispatch workflows** (403). A push triggers the workflow; a settings change is Michael's click. Pages is set to GitHub Actions; `.nojekyll` at the root and in `site/` keeps Jekyll off either way.
- **Pushes made by the workflow's own token start no workflows**, which is why the verify job and the build run in one workflow.
- **Windows paths in Python patch scripts:** a backslash in a normal string breaks (`\U` is an escape). Use forward slashes or raw strings; write long scripts to a file (the scratchpad) rather than a heredoc.
- **Line endings:** `.gitattributes` makes everything LF; git's CRLF warnings on Windows are harmless.
